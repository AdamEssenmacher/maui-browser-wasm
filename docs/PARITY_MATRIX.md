## Current browser coverage snapshot
- Complete: `Window`, `ContentPage`, `ContentView`, stack/grid/absolute layout mapping, `Button`, `CheckBox`
- Partial: `Page`, `NavigationPage`, `ScrollView`, `FlexLayout`, `Label`, `Entry`, `Editor`, `SearchBar`, `RadioButton`, `Switch`, `Slider`, `Picker`, `DatePicker`, `TimePicker`, `Stepper`, `ProgressBar`, `ActivityIndicator`, `Image`, `ImageButton`, `Border`, `Shapes.Ellipse`, `Shapes.Line`, `Shapes.Path`, `Shapes.Polygon`, `Shapes.Polyline`, `Shapes.Rectangle`, `Shapes.RoundRectangle`, `GraphicsView`, `CollectionView`, `CarouselView`, `IndicatorView`, `RefreshView`
- Missing: `SwipeView`, `WebView`
- Shared core substrate: `IView.Clip` (`RectangleGeometry`/`RoundRectangleGeometry`), `IView.Shadow` (solid paint), and `IView.Background` (`SolidPaint` + `LinearGradientPaint`) are implemented in the common browser mapper.
- Styling/presentation proof: showcase pages (`showcase-page-home`, `showcase-page-text-input`, `showcase-page-form-media`, `showcase-page-layout-collection`) now validate MAUI style-system behavior (`implicit`, `explicit`, `BasedOn`, `StyleClass`, `DynamicResource`) on top of parity handlers.
- CollectionView note: Mirage now uses a MAUI-shaped handler chain with deterministic incremental updates and equality-based selection sync on the non-virtualized runtime path; grouped/reorder/full anchoring parity remains documented as partial.
- CarouselView note: Mirage now uses a dedicated MAUI-shaped `ItemsViewHandler<CarouselView>` parity path with snap scrolling, `Position`/`CurrentItem` sync, peek/swipe/loop handling, `VisibleViews`/`IsDragging` updates, and linked `IndicatorView` proof; bounce physics and inherited `ItemsUpdatingScrollMode` limits remain documented as partial.
- RefreshView note: Mirage now uses a MAUI-shaped `RefreshView` handler on the ControlNode path with handler-owned chrome, child scroll-source rebinding for `ScrollView`/items hosts, deterministic trigger + pull diagnostics, and a dedicated runtime pull seam; native overscroll elasticity/visual affordance fidelity remains browser-limited.
- Label note: Mirage now covers core label mapper parity plus controls text-source projection (`FormattedText`, `TextType`, `TextTransform`) with deterministic safe-subset HTML sanitization; remaining label gaps are limited to HTML breadth and span gesture hit-region parity.
- Entry note: Mirage now uses a MAUI-shaped `Entry` handler with a Mirage-owned input host, including deterministic clear-button behavior, focus command routing, and two-way cursor/selection synchronization; IME composition depth remains partial.
- Editor note: Mirage now uses a MAUI-shaped `Editor` handler with a Mirage-owned textarea host, including controls remap (`Text` + `TextTransform`), two-way cursor/selection synchronization, and completed-on-blur semantics; residual browser IME edge cases remain partial.
- RadioButton note: Mirage now uses a MAUI-shaped `RadioButton` handler on the ControlNode path with a Mirage-owned host (`input[type=radio]` + content slot), including two-way checked synchronization, group-authoritative MAUI selection flow, and deterministic content/style projection; native radio chrome fidelity remains browser-approximated.
- Picker note: Mirage now uses a MAUI-shaped `Picker` handler on the ControlNode path with a native `select` host, deterministic placeholder/title-color behavior, MAUI-authored `ItemsSource` / `SelectedItem` / `ItemDisplayBinding` refresh, and `IsOpen` request roundtrip through the generic picker-open seam; native popup visibility and vertical text alignment remain browser-limited.
- DatePicker note: Mirage now uses a MAUI-shaped `DatePicker` handler on the ControlNode path with deterministic nullable-date/min-max projection, ISO browser wire formatting, and two-way `IsOpen` roundtrip via the generic runtime picker-open seam; full custom date format breadth remains explicit subset behavior.
- TimePicker note: Mirage now uses a MAUI-shaped `TimePicker` handler on the ControlNode path with deterministic `Time`/`Format` projection, two-way `IsOpen` roundtrip via a generic runtime picker-open seam, and explicit browser-native format-depth subset behavior (`hh:mm`/`hh:mm:ss`).
- ProgressBar note: Mirage now uses a MAUI-shaped `ProgressBar` handler on the ControlNode path with a native `progress` host, deterministic `[0,1]` clamping, and `ProgressColor` accent projection; native track/background styling remains browser-limited.
- GraphicsView note: Mirage now uses a MAUI-shaped `GraphicsView` handler on the ControlNode path with a DPR-aware native `canvas` host, batched Wave 1 draw-command replay, coalesced invalidation, pointer/hover routing through the `IGraphicsView` interaction surface, and deterministic plain-text fallback for `DrawText(IAttributedText, ...)`; `DrawImage`, attributed span styling/advanced text measurement, non-solid stroke-paint breadth, and broader clip/path fidelity remain explicit Wave 2 divergences.
- ImageButton note: Mirage now uses a MAUI-shaped `ImageButton` handler on the ControlNode path with a provider-managed `button` + secondary `img`, deterministic `Pressed`/`Released`/`Clicked` synthesis, and full async source-lifecycle handling aligned with current Mirage image parity depth.
- Page note: Mirage now includes a dedicated MAUI-shaped `MiragePageHandler` for `Page.Title` projection with active-runtime ownership; `NavigationPage` remains the title authority for navigation-stack children.
